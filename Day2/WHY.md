The rich Quote model gives the domain a small amount of real behavior instead of leaving everything as data. In the original anemic model, a quote was just a container with public setters, so the application had to remember rules in many places. With the current model, the quote itself knows how to validate its own values, how to be created safely, and how to be deleted without losing its identity. That makes the rules easier to see and harder to bypass.

Quote.Create(author, text) is better than allowing arbitrary object construction because it forces all new quotes to pass through the same validation path. A caller cannot accidentally create a quote with an empty author, a very long author, or a blank text value. The domain invariants are simple but useful: author must be between 1 and 200 characters, and text must be between 1 and 1000 characters. These checks prevent invalid state before it reaches the database or API layer.

Keeping Text private and set only during creation also protects the domain rule. If the text were mutable later, a caller could change it after creation and break the intended length rule or the meaning of the quote. Soft deletion through Delete() keeps deletion behavior inside the domain model as well. A quote can be marked deleted in one place, instead of having callers silently remove it from storage in different ways.

A concrete example: a client could create a quote with an empty text string and save it, and later the app might show it in a list. The rich model rejects that quote at creation time, so the bug never reaches the system.
