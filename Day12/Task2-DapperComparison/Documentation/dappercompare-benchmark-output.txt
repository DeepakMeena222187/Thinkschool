ROOT CAUSE: SQL Server infers a bare `CASE WHEN ... THEN 1 ELSE 0 END` (no cast)
as `int`, but QuoteListItemDto.IsOwnedByCurrentUser is `bool`. Dapper's
constructor-based materialization for records requires an exact per-parameter
type match, so it could not find a matching constructor and threw at query
time instead of coercing int -> bool. EF Core's LINQ projection never hit this
because `q.OwnerId == request.CurrentUserId` is typed as `bool` in C# from the
start, so EF Core itself emits the CAST(... AS bit) in the generated SQL.

FIX APPLIED: wrapped the CASE in CAST(... AS BIT) in both
Features/Quotes/GetQuoteListQueryDapperHandler.cs and the benchmark's copy of
the SQL in Benchmarks/DapperComparisonBenchmark.cs:

  CAST(CASE WHEN OwnerId = @CurrentUserId THEN 1 ELSE 0 END AS BIT) AS IsOwnedByCurrentUser
