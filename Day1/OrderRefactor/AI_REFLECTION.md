# AI Reflection

Claude got the main refactoring idea right by extracting the pricing, discount, shipping, and tax calculation from OrderService into a small strategy abstraction. This made OrderService more focused on orchestration and gives the pricing rules a place to evolve independently. However, Claude also deleted the Legacy/OrderController.cs file during the refactor. I caught that by checking git status and restored the file before committing. That showed me why reviewing the diff is more important than trusting an AI-generated change.

Copilot saved time by generating the xUnit validation tests from short comments. It created tests for negative and zero quantities in the same style as the existing tests, and the final suite passed all 6 tests. I still had to review its suggestions because Copilot also changed OrderService to add negative and zero quantity validation. The DTO already contains a Range validation rule for quantity, so I had to consider whether adding the same rule at the service layer was intentional or duplicated responsibility. I also noticed that the existing item-count validation test already covered the third requested scenario, so adding another identical test would have created unnecessary duplication.

If production were broken at 2 AM, I would reach for the code and tests first rather than relying on either AI blindly. AI is useful for generating options and accelerating repetitive work, but the actual diff, application behavior, and test results are what I would trust. The biggest lesson was that AI can produce a technically valid change that is still wrong for the task.
